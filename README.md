# Aki Dev — Discord Control

Full-stack Discord bot + web dashboard, styled monochrome/cinematic. The backend and bot run in one Node.js service so the web can issue real actions through the same process.

## Features

36 real bot features via slash commands:

`/ping` · `/help` · `/server` · `/userinfo` · `/avatar` · `/botinfo` · `/rank` · `/balance` · `/daily` · `/work` · `/leaderboard` · `/poll` · `/8ball` · `/roll` · `/coinflip` · `/remind` · `/afk [reason] [image_url] [media]` · `/warn` · `/warnings` · `/clear` · `/slowmode` · `/lock` · `/unlock` · `/kick` · `/ban` · `/timeout` · `/role` · `/legit` · `/ticket-setup` · `/role-panel` · `/announce` · `/vc-join` · `/vc-leave` · `/auto-voice` · `/welcome-setup` · `/goodbye-setup`

The web dashboard has guild selection, live runtime metrics, voice controls, command lab, activity feed, Discord OAuth, Google OAuth, animated 3D UI, and an AFK Studio. The AFK profile is stored per server/user and supports an optional direct image/GIF URL.

The dashboard also supports a configurable channel for a reaction-role panel (Member auto-role plus basic opt-in ping roles), direct announcement posting from the web panel, and a `+legit` reaction shortcut. Reaction-role reactions only work on the active message ID stored in `reaction_role_panels`, with each emoji resolved from `reaction_role_bindings`. The `+legit` shortcut is disabled until `LEGIT_TARGET_USER_ID` is configured in the environment; no personal Discord ID is hard-coded in the repository.

 
## Role and runtime troubleshooting

- In **Dashboard → Auto-role & panels**, select the text channel and click **POST ROLE PANEL** again after deploying. The new panel includes both Unicode reaction emojis and matching emoji buttons; the buttons show an ephemeral success or permission error.
- Make sure the bot has **Manage Roles**, **Add Reactions**, **Read Message History**, **Send Messages**, and **Embed Links** in the selected channel. Place the bot's highest role above `👥 Member` and every opt-in ping role.
- Select the desired channel in **Discord log channel** and save it. Reaction-role errors, dashboard operation failures, runtime promise errors, and Discord client errors are sent there when the bot is online and can access the log channel.
- `/welcome-setup channel:#welcome` and `/goodbye-setup channel:#goodbye` configure join/leave announcements.
- `/rank` and `/leaderboard type:Levels / XP` use message XP (one award per member per 60 seconds). `/daily`, `/work`, `/balance`, and `/leaderboard type:Coins / Xu` use virtual server coins only.
- Persistent XP, coins, role panel bindings, and dashboard sessions require a working `DATABASE_URL`. Without Postgres, fallback data is in memory and is lost when the process restarts. The Render Blueprint now uses the paid `basic-256mb` Postgres plan with 1 GB disk; this incurs charges. Render Free Postgres expires after 30 days, has a 14-day grace period, and has no backups. See the [Render Free plan limitations](https://render.com/docs/free).


## Important

Use official bot OAuth and the Discord Developer Portal. OAuth access/refresh tokens in persistent sessions are AES-256-GCM encrypted before they are written to PostgreSQL. Set `SESSION_ENCRYPTION_KEY` to a random secret in Render (for example, generated by `openssl rand -hex 32`); if unset, the app uses the configured OAuth client secret as key material.

Render's Free web service can sleep after 15 minutes with no inbound traffic, so Free is good for testing but not for real 24/7 voice uptime.

## Local setup

1. Copy `.env.example` to `.env`.
2. Fill the Discord bot and OAuth credentials.
3. Put a Postgres URL in `DATABASE_URL` or leave it empty for an in-memory fallback.
4. `npm ci`
5. `npm start`

### Database migrations and backups

The schema is managed by ordered SQL files in `migrations/`. Applied migration filenames are recorded in `schema_migrations`; existing tables are preserved and migrations use idempotent DDL for older databases.

Run `npm run backup` to export public-schema tables into a gzip-compressed JSON file under `backups/` (or set `BACKUP_DIR`). The export is not encrypted and is not copied off-host automatically. Move backups to secure external storage and protect them like production data.

Open `http://localhost:10000`.

## Discord Developer Portal

Create an Application + Bot and copy:

- `DISCORD_TOKEN`
- `DISCORD_CLIENT_ID`
- `DISCORD_CLIENT_SECRET`

Enable the Gateway intents used by this project, including Message Content for the prefix/AFK message listener. The AFK slash command supports either `image_url` or an uploaded `media` attachment.

OAuth2 redirect:

- Discord: `https://YOUR-DOMAIN/auth/discord/callback`

Invite the bot to your server with `bot` + `applications.commands` scopes and the permissions needed by the moderation/voice features you want to use.

## Google OAuth

Create a Google OAuth Web client.

Redirect URI:

- `https://YOUR-DOMAIN/auth/google/callback`

Set `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`.

Google-only sessions do not know the user's Discord guild permissions; use Discord login for server control. The Google button is included so the dashboard itself supports Google OAuth.

## Render

This repo includes `render.yaml` for a Web Service + Postgres.

Deploy from GitHub with Render Blueprint. Set secret environment variables in the Render Dashboard:

`DISCORD_TOKEN`, `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, and `SESSION_ENCRYPTION_KEY` (recommended). If the encryption key changes, existing encrypted OAuth tokens cannot be decrypted and users may need to log in again.

For the current deployed service, set `SITE_URL` to `https://aki-discord-control-6yfp.onrender.com` and use the exact OAuth callback `https://aki-discord-control-6yfp.onrender.com/auth/discord/callback`. If you change the service name/domain, update `SITE_URL` and the OAuth redirect URI again.

For 24/7 bot + voice, use a plan that does not sleep.
